<h2 id="왜-평가지표가-필요한가">왜 평가지표가 필요한가?</h2>
<p>모델을 학습시킨 후에는 반드시 성능을 측정해야 합니다. 이때 어떤 기준으로 측정하느냐에 따라 같은 모델도 다르게 평가될 수 있습니다.</p>
<p>예를 들어 산불 감지 모델이 있다고 생각해 봅시다. 실제로 산불이 발생할 확률은 매우 낮습니다. 이 모델이 항상 &quot;산불 없음&quot;으로만 예측한다면 정확도는 98%에 달할 수 있습니다. 하지만 실제 산불을 단 한 번도 감지하지 못한 쓸모없는 모델입니다.</p>
<blockquote>
<p>문제의 성격에 맞는 <strong>적절한 평가지표를 선택하는 것</strong>이 모델 성능을 올바르게 판단하는 핵심입니다.</p>
</blockquote>
<hr />
<h2 id="분류-모델-평가지표">분류 모델 평가지표</h2>
<p><img alt="" src="https://velog.velcdn.com/images/mommers/post/fede3406-9391-4e50-b2fe-2d6da0317fd1/image.png" /></p>
<h3 id="혼동-행렬-confusion-matrix">혼동 행렬 (Confusion Matrix)</h3>
<p>혼동 행렬은 분류 모델이 예측한 결과와 실제 값을 비교하여 정리한 표입니다. 모든 분류 평가지표의 기반이 됩니다.</p>
<table>
<thead>
<tr>
<th></th>
<th>예측: Negative</th>
<th>예측: Positive</th>
</tr>
</thead>
<tbody><tr>
<td><strong>실제: Negative</strong></td>
<td>TN (True Negative)</td>
<td>FP (False Positive)</td>
</tr>
<tr>
<td><strong>실제: Positive</strong></td>
<td>FN (False Negative)</td>
<td>TP (True Positive)</td>
</tr>
</tbody></table>
<p>각 항목의 의미는 다음과 같습니다.</p>
<ul>
<li><strong>TP (True Positive)</strong>: 양성으로 예측했고, 실제도 양성인 경우</li>
<li><strong>TN (True Negative)</strong>: 음성으로 예측했고, 실제도 음성인 경우</li>
<li><strong>FP (False Positive)</strong>: 양성으로 예측했지만, 실제는 음성인 경우 — 1종 오류</li>
<li><strong>FN (False Negative)</strong>: 음성으로 예측했지만, 실제는 양성인 경우 — 2종 오류</li>
</ul>
<blockquote>
<p>TP와 TN은 <strong>올바른 예측</strong>, FP와 FN은 <strong>잘못된 예측</strong>입니다.</p>
</blockquote>
<hr />
<h3 id="정확도-accuracy">정확도 (Accuracy)</h3>
<p>전체 예측 중 올바르게 예측한 비율입니다.</p>
<p><img alt="" src="https://velog.velcdn.com/images/mommers/post/b04669cb-f3fd-4a45-8c1d-656eaf2c7efa/image.png" /></p>
<p>$$Accuracy = \frac{TP + TN}{TP + TN + FP + FN}$$</p>
<p>직관적으로 이해하기 쉽고 가장 많이 쓰이는 지표이지만, <strong>클래스 불균형</strong> 상황에서는 신뢰하기 어렵습니다. 앞서 산불 예시처럼 한쪽 클래스가 압도적으로 많으면 정확도만으로는 모델이 제대로 학습됐는지 판단할 수 없습니다.</p>
<hr />
<h3 id="정밀도-precision">정밀도 (Precision)</h3>
<p>양성으로 예측한 것 중 실제로 양성인 비율입니다.</p>
<p><img alt="" src="https://velog.velcdn.com/images/mommers/post/61b4f09a-b5a2-4255-bd7c-e4e6092a776f/image.png" /></p>
<p>$$Precision = \frac{TP}{TP + FP}$$</p>
<p><strong>FP를 줄이는 것</strong>이 목표입니다. 즉, 양성이라고 예측한 결과가 얼마나 믿을 만한지를 나타냅니다. 스팸 메일 필터처럼 정상 메일을 스팸으로 잘못 분류하면 안 되는 상황에서 중요한 지표입니다.</p>
<hr />
<h3 id="재현율-recall">재현율 (Recall)</h3>
<p>실제 양성인 것 중 양성으로 올바르게 예측한 비율입니다.</p>
<p><img alt="" src="https://velog.velcdn.com/images/mommers/post/25e84dbb-cf9c-4d0f-a61a-d5796f808312/image.png" /></p>
<p>$$Recall = \frac{TP}{TP + FN}$$</p>
<p><strong>FN을 줄이는 것</strong>이 목표입니다. 즉, 실제 양성을 얼마나 빠짐없이 잡아내는지를 나타냅니다. 암 진단이나 공정 이상 탐지처럼 실제 양성을 놓쳐서는 안 되는 상황에서 중요한 지표입니다.</p>
<blockquote>
<p>정확도(Accuracy)가 높더라도 재현율(Recall)이 낮으면 실제 문제를 제대로 감지하지 못하는 모델일 수 있습니다. 두 지표를 함께 확인하는 습관이 중요합니다.</p>
</blockquote>
<hr />
<h3 id="f1-score">F1 Score</h3>
<p>정밀도와 재현율의 <strong>조화평균</strong>입니다. 두 지표를 하나의 값으로 균형 있게 표현합니다.</p>
<p><img alt="" src="https://velog.velcdn.com/images/mommers/post/138f073a-d663-4c5d-b431-908b94f17dfa/image.png" /></p>
<p>$$F1 = \frac{2 \times Precision \times Recall}{Precision + Recall}$$</p>
<p>정밀도와 재현율 중 하나가 극단적으로 낮으면 F1 Score도 낮게 나옵니다. 두 지표가 모두 높아야 F1 Score가 높아지는 구조입니다.</p>
<p>클래스 불균형이 있거나 정밀도와 재현율을 동시에 고려해야 할 때 유용하게 사용됩니다.</p>
<hr />
<h3 id="정밀도와-재현율의-관계">정밀도와 재현율의 관계</h3>
<p>정밀도와 재현율은 일반적으로 <strong>트레이드오프(Trade-off)</strong> 관계에 있습니다. 하나를 높이면 다른 하나가 낮아지는 경향이 있습니다.</p>
<table>
<thead>
<tr>
<th>상황</th>
<th>우선할 지표</th>
<th>이유</th>
</tr>
</thead>
<tbody><tr>
<td>스팸 메일 필터</td>
<td>정밀도</td>
<td>정상 메일을 스팸으로 잘못 분류(FP)하면 안 됨</td>
</tr>
<tr>
<td>암 진단, 공정 이상 탐지</td>
<td>재현율</td>
<td>실제 이상을 놓치는 것(FN)이 더 치명적</td>
</tr>
<tr>
<td>일반적인 분류 문제</td>
<td>F1 Score</td>
<td>두 지표를 균형 있게 고려</td>
</tr>
</tbody></table>

<h2 id="회귀-모델-평가지표">회귀 모델 평가지표</h2>
<p>회귀 모델은 연속적인 수치를 예측하기 때문에 분류처럼 맞고 틀림이 아닌, <strong>예측값과 실제값의 차이(오차)</strong> 를 기준으로 성능을 평가합니다.</p>
<h3 id="mae-mean-absolute-error">MAE (Mean Absolute Error)</h3>
<p>예측값과 실제값의 차이를 <strong>절댓값</strong>으로 취한 뒤 평균을 구합니다.</p>
<p>$$MAE = \frac{1}{n}\sum_{i=1}^{n}|y_i - \hat{y}_i|$$</p>
<ul>
<li>오차를 그대로 평균 낸 것이므로 <strong>직관적으로 해석하기 쉽습니다.</strong></li>
<li>모든 오차를 동등하게 취급하기 때문에 <strong>이상치(Outlier)에 비교적 덜 민감합니다.</strong></li>
<li>MAE가 낮을수록 좋은 모델입니다.</li>
</ul>
<hr />
<h3 id="mse-mean-squared-error">MSE (Mean Squared Error)</h3>
<p>예측값과 실제값의 차이를 <strong>제곱</strong>한 뒤 평균을 구합니다.</p>
<p>$$MSE = \frac{1}{n}\sum_{i=1}^{n}(y_i - \hat{y}_i)^2$$</p>
<ul>
<li>오차를 제곱하기 때문에 <strong>큰 오차에 더 민감하게 반응합니다.</strong></li>
<li>오차가 클수록 패널티가 기하급수적으로 커지므로, 큰 오차를 특히 줄이고 싶을 때 유용합니다.</li>
<li>제곱 단위로 계산되므로 원래 데이터의 단위와 달라 직관적인 해석이 어려울 수 있습니다.</li>
<li>MSE가 낮을수록 좋은 모델입니다.</li>
</ul>
<hr />

</blockquote>

<h2 id="scikit-learn으로-평가지표-사용하기">scikit-learn으로 평가지표 사용하기</h2>
<h3 id="분류-모델">분류 모델</h3>
<pre><code class="language-python">from sklearn.metrics import confusion_matrix
from sklearn.metrics import accuracy_score, precision_score, recall_score, f1_score
from sklearn.metrics import classification_report

# 개별 지표 확인
print(&quot;정확도: &quot;, accuracy_score(y_test, y_pred))
print(&quot;정밀도: &quot;, precision_score(y_test, y_pred))
print(&quot;재현율: &quot;, recall_score(y_test, y_pred))
print(&quot;F1-Score: &quot;, f1_score(y_test, y_pred))

# 혼동 행렬
print(confusion_matrix(y_test, y_pred))

# 전체 지표 한 번에 확인
print(classification_report(y_test, y_pred))</code></pre>
<h3 id="회귀-모델">회귀 모델</h3>
<pre><code class="language-python">from sklearn.metrics import mean_absolute_error, mean_squared_error

print(&quot;MAE: &quot;, mean_absolute_error(y_test, y_pred))
print(&quot;MSE: &quot;, mean_squared_error(y_test, y_pred))</code></pre>
