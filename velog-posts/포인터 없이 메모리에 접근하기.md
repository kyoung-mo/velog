<ul>
<li>메모리 접근에 포인터가 꼭 필요한가?</li>
<li>포인터 없이 메모리에 접근하는 방법을 메모리 직접접근  ↔ 메모리 간접 접근</li>
</ul>
<blockquote>
<p>0x3000_0000 = 100;</p>
</blockquote>
<p>앞에도 상수, 100도 상수이므로 상수를 대입할 수 없다. 0x3000_0000 이 주소값이라고 표시해주어야 한다.</p>
<blockquote>
<p><strong>`</strong>(<strong>)`</strong> 0x30000000 = 100;</p>
</blockquote>
<p>포인터로 캐스팅 했으나, 100을 저장하려면 할당 받을 메모리의 크기가 지정되어야 한다.</p>
<blockquote>
<p>(<code>int</code>) 0x30000000 = 100;</p>
</blockquote>
<p>메모리에 쓰는 값들은 데이터 값이므로  unsigned로 표현한다.</p>
<blockquote>
<p>(<code>unsigned int</code>) 0x30000000 = 100;</p>
</blockquote>
<p>컴파일러가 최적화를 수행하지 않도록 → 테스트코드나, 딜레이용으로 만든 코드의 최적화를 막는 기능을 함</p>
<blockquote>
<p>(<code>volatile unsigned int</code>) 0x30000000 = 100;
#<code>volatile</code> 은 휘발성을 방지해주기 위해 사용</p>
</blockquote>
<p>매번 이렇게 긴 표현을 사용하면 불편하니, 매크로를 사용</p>
<blockquote>
<p>#define PA  ((<code>volatile unsigned int</code>) 0x30000000)</p>
<p>void int(void){
  PA |=(0x7&lt;&lt;5);  //메모리 PA[7:5]를 1로 설정하여 LED를 끔
}</p>
</blockquote>
<p>실행될 환경의 메모리 레이아웃이 어떻게 구성되어 있는지 정확하게 파악될 때만 사용!
그렇지 않은 곳에서 사용하면 비정상적인 메모리 접근이 되어 프로그램이 크래시 될 수도 있다.</p>
<h3 id="왜-사용하나">왜 사용하나?</h3>
<p>포인터 저장하기 위한 메모리 사용 안해서 → 메모리 절약
간접 접근하지 않아 절차를 한 단계 줄인다. → 속도 증가</p>
<ul>
<li><strong>펌웨어쪽에서만 사용한다.</strong></li>
</ul>
